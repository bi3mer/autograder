# Week 7 - Problem 1: To-Do List

A to-do list keeps tasks in order. New tasks go on the end, urgent ones jump to the front, and finished ones are removed. This program keeps one list of tasks and changes it as the user types commands, until the user enters a blank command.

The program is four functions. `print_tasks` shows the list. `yes_or_no` asks the user to confirm. `finish_task` takes one task off the list once the user confirms it. `main` reads each command and does what it asks.

## Input

Every command is read with the prompt `"Command: "`. A blank command ends the program. Commands work in any case, so `add`, `Add`, and `ADD` are the same command:

| Command | What it does                                                                                                            |
| ------- | ----------------------------------------------------------------------------------------------------------------------- |
| `add`   | Asks for a task with the prompt `"Task: "`, then adds it to the end of the list.                                        |
| `first` | Asks for a task with the prompt `"Task: "`, then adds it to the front of the list.                                      |
| `done`  | Asks for a task number with the prompt `"Number: "`, then asks to confirm and takes that task off. Task 1 is the first. |
| `list`  | Prints the list.                                                                                                        |

Any other command prints `Unknown command.` and the program asks for the next command. A task can be any text, including spaces and digits.

A `done` for a real task asks `"Yes or no? "` before taking it off. The valid answers are `yes`, `y`, `no`, and `n`, in any case, so `YES` and `N` count too. Anything else asks the same question again.

## Processing

- `print_tasks(tasks)`
  - Prints the tasks, numbered from 1.
- `yes_or_no()`
  - Starts from your function in [Yes or No Function](w5i1.html), changed to take answers in any case and to take `y` and `n` too.
  - Asks `"Yes or no? "` until the answer is valid, then returns `True` for `yes` or `y` and `False` for `no` or `n`.
- `finish_task(tasks, text)`
  - Takes the list of tasks and the text typed at the `"Number: "` prompt.
  - Text that is not a whole number, or a number with no task, leaves the list as it was and asks nothing.
  - For a real task, looks the task up by its index, prints `Finish Buy milk?`, and calls `yes_or_no()`. On yes, takes the task off the list with `pop()`. On no, leaves the list as it was.
  - Changes the list itself and returns nothing, like `curve` in [We Do: Curve the Scores](https://bi3mer.github.io/lectures/cs230/09-changing-lists.html#24).
- `main()`
  - Takes no parameters. Starts with an empty list and asks for commands until the command is blank.
  - Uses `append()` for `add`, `insert()` for `first`, `print_tasks` for `list`, and `finish_task` for `done`.

Each `except` names the exception it catches.

_Question: `finish_task` returns nothing. Why does `main` still see the task disappear from the list?_

## Output

Each `done` for a number with no task prints one line: `Not a task number.` or `There is no task 9.` A `done` for a real task prints `Finish Buy milk?` before asking, and after the answer prints `Done: Buy milk` for yes or `Kept: Buy milk` for no. Each `list` prints the numbered tasks or `Nothing to do.` The last line is `Tasks left: 2`.
